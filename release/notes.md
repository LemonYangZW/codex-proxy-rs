# v3.11.0-exp.2

## 实验说明

Codex 降智缓解实验版，基线升级至正式版 v3.11.0，面向希望体验 [#144](https://github.com/zyycn/codex-proxy-rs/issues/144) 中方案的用户。
本版本接续 `v3.10.0-exp.1`、`v3.10.0-exp.2`，采用简短的 `exp.N` 命名；旧版本标签与产物保留。
实验功能独立于主版本，实际效果仍需使用反馈验证，不保证改善模型质量，也不承诺合入正式版。

## 基于 v3.11.0 的新特性

- 新增模型定价管理，支持自定义单价、倍率和手动同步来源价目，可预览差异并勾选需要同步的模型。支持清除人工覆盖、删除非内置模型价格，内置价格仅允许覆盖。价格按请求保存快照，后续改价不重算历史费用
- 支持在管理端配置 OpenAI 客户端身份，选择 CLI 或 Desktop 预设、跟随最新版本或自定义版本，API 密钥可单独覆盖通用配置
- 支持在「系统设置 → 安全与访问」修改管理员密码，验证当前密码后保存，已登录的管理员需使用新密码重新登录
- API 密钥支持手动清零日额度、7 日额度或全部已用金额，原重置时间保持不变
- 自定义 OpenAI 中转缺少额度、订阅资料或额度重置接口并返回 404 时，账号辅助请求会尝试官方端点，继续沿用账号的出站代理设置，不改变推理请求地址
- 最终返回的 `server_is_overloaded`、`slow_down` 按客户端可重试的 `server_error` / 503 交付，同时保留内部错误分类。提高明确容量拒绝对 Smart 调度的惩罚权重，普通错误、时间衰减与会话亲和规则保持不变
- 修复取消后的 OpenAI 文件读取在服务关闭期间仍继续等待的问题
- 修复表格列显示或隐藏后横向滚动状态未及时更新的问题，缩小使用统计中模型与推理强度的间距
- 更新说明使用独立 Markdown 样式区域，修复列表圆点缺失并避免与页面样式互相影响

## 本次变化（实验相关）

- 新增 OpenAI turn-state 密文长度的可观测记录：解码 `x-codex-turn-state` 令牌长度（不解码令牌内容本身），在使用记录列表与详情中展示该长度启发值，辅助排查疑似模型降智情况
- 合入 [#155](https://github.com/zyycn/codex-proxy-rs/pull/155)：各模型独立刷新 State，成功后立即写入缓存；其他失败模型继续重试，互不等待。单模型前三轮各发起 1 个探针，之后每轮最多 3 个，接受首个成功结果并取消其余请求
- 合入 [#162](https://github.com/zyycn/codex-proxy-rs/pull/162)，完善 State 重写的刷新、恢复与业务请求准入：
  - **可配置分阶段重试**：设置页可调整探针并发与轮间等待，默认 3 并发、6 秒，范围分别为 1～10 和 1～300 秒。每账号／模型前三轮固定为单探针、轮后等待 6 秒，第四轮起使用配置；手动与后台共用规则
  - **独立连接与 Header 准入**：每个探针使用独立 HTTP/1.1 代理连接，仅接受 HTTP 200、原始长度恰为 292 字节、以 `gAAAAA` 开头的 ASCII State Header。合法 Header 到达即关闭响应，不再等待完整 SSE；无效结果不写入缓存
  - **Redis 恢复与按需刷新**：按账号／模型保存票据，网关 TTL 为 60 分钟；重启不延长到期时间。仅对缺失、无效、过期或剩余不足 10 分钟的票据发起刷新，手动操作也跳过仍有效且未临期的模型
  - **缺票暂停接单**：启用 State 重写的账号／模型缺少有效票据、鉴权绑定变化或 Redis 不可用时，不再直接向上游发送业务请求；有其他合格账号时继续选号。增加票据失效原因与选号排除日志，便于排查
  - **修复有效票据提前失效**：票据改为绑定实际鉴权材料。普通 Cookie 写回、账号名称及调度设置修改不再使票据提前失效；真实鉴权变化拒绝旧票据与迟到探测结果，禁用或删除账号仍取消探测并清票
  - **改善后台调度**：后台每账号每轮只发一批探针，最多两个账号同时刷新，避免某个账号持续失败阻塞后续账号；429 冷却仍按账号／模型独立保留
- 手动刷新实时显示逐模型结果，支持停止刷新、关闭弹窗及离开页面时取消未完成请求，保留已成功结果
- 后台启动后执行一轮，每轮结束后随机等待 53～55 分钟；手动刷新不重置后台周期

## 安装与使用

```bash
docker pull ghcr.io/zyycn/codex-proxy-rs:3.11.0-exp.2
```

- Docker 镜像支持 Linux amd64、arm64；二进制归档提供 Linux amd64、Linux arm64、macOS arm64，包含管理端静态资源。
- 从本页附件下载 `compose.yaml`、`config.example.yaml` 和 `checksums.txt`。Compose 已固定本版本镜像并合并隔离配置，使用独立项目名，管理端默认端口为 `8081`。
- 首次安装使用独立目录、配置、PostgreSQL、Redis 和数据目录，按[实验部署说明](https://github.com/zyycn/codex-proxy-rs/blob/v3.11.0-exp.2/deploy/experimental.md)操作。
- 功能默认关闭。先保存并测试动态代理，在设置页确认风险、启用全局开关，再逐账号选择重写模型；配置与边界见[功能说明](https://github.com/zyycn/codex-proxy-rs/blob/v3.11.0-exp.2/docs/session-keepalive-design.md)。
- 系统设置重新归类为「网关调度 / 上游配置 / 模型定价 / 安全与访问 / 数据备份」，按需加载对应内容，模型映射归入上游配置
- Fast 模式统一由密钥绑定分组控制，移除重复的全局开关，分组使用「默认 / 关闭」分段选择
- 简化客户端身份配置，自定义版本集中展示可编辑参数，加载时使用骨架屏稳定布局
- 统一密钥与代理名称展示，优化额度重置、价格同步和批量清除弹窗，精简提示文案与操作按钮

归档提供校验和与 GitHub 构建产物证明；镜像附带 SBOM、构建来源证明及 cosign 签名。

## 使用须知

- 本次实验版基线由 v3.10.0 升级至 v3.11.0，会依次执行新增迁移 `0016`（客户端身份与模型定价字段，并删除全局 Fast 字段）、`0017`（会话保活持久化字段）、`0018`（State 重写并发数与重试间隔配置，默认 3／6，不影响已有配置）、`0019`（turn-state 密文长度记录）。已发布的 `0001`～`0015` 保持不变，账号、分组及历史使用记录保留。升级前请停止旧应用并备份数据库，迁移后不要直接运行旧二进制，回退需恢复备份
- 早期从 `v3.10.0-exp.1`／`v3.10.0-exp.2` 升级的实例注意：这两个版本里的会话保活迁移编号是 `0016`／`0017`，本版本基线切到 v3.11.0 后统一让位给正式版的 `0016_client_profiles_and_model_pricing.sql`，会话保活相关迁移改用 `0017`／`0018`。内容与效果不变，仅编号顺延；升级前建议核对自己实例 `_sqlx_migrations` 的实际记录，不要凭空修改 checksum 绕过校验
- 若原先启用了全局 Fast 禁用，请在升级前将需要限制的分组设为「关闭」，并为未分组密钥绑定相应分组。外部运行设置请求移除 `disableFast` 字段，分组接口仍保留该字段
- 升级后管理员需重新登录一次，API 密钥身份会话不受影响。模型价格用于本地费用估算和额度控制，不代表上游实际扣费
- **升级后的接单变化**：启用范围内首次取得有效票据前，对应账号／模型暂停接单；若没有其他合格账号，请求可能返回 503。Redis 数据丢失后需重新获取票据，保持 Redis 数据卷和配置命名空间稳定
- **刷新会产生真实调用**：探针可能消耗上游额度并产生费用。手动刷新会持续重试失败模型，可停止刷新或关闭弹窗取消；独立连接不保证出口 IP 不重复，仍取决于代理池
- 292 字节、ASCII 与前缀检查是实验准入规则，不证明票据完整性、上游有效期或模型质量。按账号／模型跨轮次覆盖 State 与官方按轮次隔离的合同存在已知偏离，真实业务兼容性仍需验证
- 不与稳定实例共用数据库或数据目录，实验库不能原地降级回稳定版，也不能直接混用主分支未来同编号迁移。运行过早期 PR #151 迁移或其他预览版同编号迁移的源码实例，需按部署说明核对重建与恢复边界；不要修改 `_sqlx_migrations` 的 checksum 绕过校验
- 当前按单进程、单副本运行；Redis 持久化不提供跨副本探测去重。日志可能保留 State 原文，请限制访问和保留周期，不向公开反馈粘贴真实票据或认证信息
- 本版本为 Pre-release，不设为 GitHub Latest，不覆盖 Docker `latest`；稳定更新渠道不会提示本次实验升级，主动选择 `preview` 渠道的用户可能看到预发行
